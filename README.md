# اپلیکیشن و ویجت اندروید «چند؟» (Chand Android App & Widgets)

اپلیکیشن نرخ لحظه‌ای ارز، طلا، سکه و رمزارز با طراحی مینیمال و دارک، کاملاً الهام‌گرفته از نسخه محبوب iOS چند، مجهز به **ویجت‌های تعاملی صفحه اصلی اندروید (Jetpack Glance)**.

---

## 📱 ویژگی‌ها و امکانات

* **طراحی چشم‌نواز و مدرن مشابه iOS:**
  - تم دارک عمیق (OLED Black `#000000`) با کارت‌های شیشه‌ای و حاشیه‌های ظریف.
  - پشتیبانی کامل از چینش راست‌به‌چپ (RTL) و تایپوگرافی خوانا.
  - نمایش نمودارهای نوسان روند (Sparkline) برای هر دارایی.
  - کارت نمایش قیمت، برچسب‌های درصد تغییرات روزانه (`+` به رنگ سبز و `-` به رنگ قرمز).
* **پوشش جامع بازارهای مالی ایران:**
  - **ارزها:** دلار آمریکا، یورو، درهم امارات، پوند انگلیس، لیر ترکیه، دلار کانادا، یوان چین و...
  - **طلا و مسکوکات:** سکه امامی، بهار آزادی، نیم سکه، ربع سکه، سکه گرمی، طلای ۱۸ عیار، ۲۴ عیار، مثقال.
  - **ارزهای دیجیتال:** تتر، بیت‌کوین، اتریوم، تون‌کوین، سولانا، دوج‌کوین و...
* **ویجت‌های تعاملی صفحه اصلی (Home Screen Widgets):**
  - **ویجت تکی (Small - 2x2):** نمایش یک دارایی منتخب با نرخ لحظه‌ای و درصد تغییرات.
  - **ویجت فهرستی (Medium - 4x2):** نمایش ۴ نرخ کلیدی بازار به‌همراه دکمه تازه‌سازی آنی (Instant Refresh).
  - **ویجت کامل (Large - 4x4):** نمایش جامع تمام بازارهای اصلی.
* **به‌روزرسانی دوره‌ای و بهینه باتری:**
  - استفاده از `WorkManager` جهت بروزرسانی خودکار هر ۱۵ دقیقه در پس‌زمینه.
  - زمان آخرین دریافت و وضعیت دادهٔ ذخیره‌شده در برنامه نمایش داده می‌شود؛ در نبود پاسخ معتبر، قیمت تخمینی جایگزین نمی‌شود.
* **ماشین‌حساب داخلی و تبدیل ارز:**
  - محاسبه آنی معادل تومانی هر مقدار ارز یا طلا در برگه جزئیات.

---

## 🛠️ ساختار فنی پروژه (Architecture)

* **زبان:** Kotlin
* **رابط کاربری:** Jetpack Compose + Material 3
* **فریم‌ورک ویجت:** Android Jetpack Glance 1.1.1 (رویکرد نوین و اعلانی ویجت‌های اندروید)
* **معماری:** MVVM با یک مسیر هماهنگ برای کش و همگام‌سازی قیمت‌ها
* **پردازش پس‌زمینه:** Android WorkManager 2.10
* **ذخیره‌سازی محلی:** Jetpack DataStore Preferences
* **شبکه و وب‌سرویس:** OkHttp + Gson

## 🚀 نحوه اجرا و توسعه

### ۱. اجرای پیش‌نمایش زنده در مرورگر
می‌توانید فایل `preview/index.html` را در هر مرورگری باز کنید تا شبیه‌ساز زنده اپ و ویجت‌ها را فوراً مشاهده نمایید.

### ۲. باز کردن پروژه در Android Studio
1. نرم‌افزار **Android Studio** (نسخه Ladybug / Jellyfish یا جدیدتر) را باز کنید.
2. گزینه **Open** را انتخاب کرده و مسیر پوشه پروژه را انتخاب فرمایید:
   `d:\prj\Widget I`
3. منتظر بمانید تا Gradle فرآیند Sync را انجام دهد.
4. پروژه را روی شبیه‌ساز (Emulator) یا گوشی واقعی اندروید خود اجرا کنید.

### ۳. افزودن ویجت به صفحه گوشی
1. پس از نصب اپ، در صفحه اصلی گوشی انگشت خود را روی فضای خالی نگه دارید.
2. گزینه **Widgets** یا **ابزارک‌ها** را لمس کنید.
3. در لیست، برنامه **چند؟** را انتخاب کنید و اندازه دلخواه را به صفحه بکشید.

### ۴. گزارش خطا برای تسترها

برای بیلدِ دارای Crashlytics، فایل `google-services.json` مربوط به Android app با package name برابر `com.chand.app` باید در پوشه `app/` قرار گیرد. Google Analytics برای این قابلیت نصب نشده است.

در GitHub Actions، همین محتوای JSON از Secret مخزن با نام `GOOGLE_SERVICES_JSON` به پوشه `app/` نوشته می‌شود؛ فایل محلی در Git نادیده گرفته می‌شود. بیلد Release در CI فقط صحت ساخت را می‌سنجد و تا زمان تنظیم امضای ثابت، قابل انتشار نیست.

متن حریم خصوصی در [PRIVACY.md](PRIVACY.md) است. پیش از انتشار عمومی باید آن را در یک نشانی عمومیِ پایدار منتشر و لینک آن را در صفحهٔ دانلود اپ درج کرد.

برای ساخت Release امضاشده در همین رایانه، `./scripts/release.ps1` را اجرا کنید. کلید در `local-signing/chand-release.p12` و رمز رمزگذاری‌شدهٔ مخصوص همین حساب ویندوز در `local-signing/password.dpapi` ذخیره شده‌اند؛ این پوشه وارد Git نمی‌شود. برای بکاپ قابل استفاده روی رایانهٔ دیگر، فایل `.p12` را به فضای امن منتقل کنید و رمز را با اجرای دستی `./scripts/release.ps1 -ShowRecoveryPassword` ببینید و در مدیر رمز عبور ذخیره کنید. صرفاً بکاپ گرفتن از فایل `.dpapi` برای بازیابی روی رایانهٔ دیگر کافی نیست. بدون این کلید، خروجی CI فقط برای بررسی ساخت است و امضا ندارد. APKهای Debug قبلی به‌دلیل تفاوت گواهی امضا به نسخهٔ Release تازه آپدیت نمی‌شوند.

Firebase و ارسال گزارش کرش، ANR و خطاهای محدود قیمت/ویجت به‌صورت پیش‌فرض خاموش هستند و SDK فقط پس از رضایت کاربر مقداردهی اولیه می‌شود. کاربر می‌تواند از «تنظیمات ← گزارش خودکار خطاها» رضایت بدهد یا آن را پس بگیرد. در بیلد Debug، پس از رضایت، گزینه «ارسال گزارش آزمایشی» یک گزارش غیرکشنده ثبت می‌کند؛ نتیجه را در Firebase Console → Crashlytics بررسی کنید. دادهٔ خام درخواست‌ها، توکن‌ها و متن خطاهای شبکه عمداً در گزارش‌های اختصاصی ثبت نمی‌شوند. در نصب‌های قبلی ممکن است گزارش‌های ذخیره‌شدهٔ محلی با فعال‌سازی ارسال شوند؛ خاموش‌کردن جمع‌آوری Crashlytics طبق رفتار SDK از اجرای بعدی اپ کامل می‌شود و گزارش‌های قبلاً ارسال‌شده از گوشی قابل حذف نیستند.
